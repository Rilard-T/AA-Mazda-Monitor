Текущее поведение: NavigationTemplate + ActionStrip. Surface (NavRenderer) рисует приборы. Кнопки переключают «страницу» на поверхности, без выхода из AA.

Как это работает в коде

  • NavScreen хранит текущий экран (enum: GAUGES, GRAPHS, …).
  • onGetTemplate() строит ActionStrip с кнопками; активная подсвечена.
  • NavRenderer.draw() читает NavLayoutStore.layout + текущий экран и рисует либо приборы, либо график.
  • История значений хранится в кольцевом буфере в NavData (по pid, ~5 мин, 1 Гц).
  • Переключение не пересоздаёт surface — только invalidate шаблона.

Экран «Графики» (один датчик, линия + сетка). Цвет линии настраивается.

Настройки графика (в редакторе / меню)

Цвет хранится в NavItem/GraphItem (поле color). Толщина и окно — там же. В машине перерисовка по Choreographer, как сейчас.

Сейчас границы виджета — прямоугольник, а круглый датчик занимает квадрат. Предлагается: для GAUGE рисовать круглую рамку по вписанному кругу, а ячейку (w×h) можно делать вытянутой — круг впишется, пустые углы не блокируют другие виджеты.

Инструменты редактора

Кнопки: «Выровнять по левому краю», «По центру», «Распределить равномерно». При перетаскивании показываются направляющие (синие линии) к границам соседних виджетов и линиям сетки. Долгое нажатие на виджет — меню: Датчик, Размер круга, Границы (круг/квадрат), Удалить.

Границы виджета: Круг (по умолчанию для GAUGE) Квадрат Без рамки. Круглая рамка рисуется по min(w,h)/2, поэтому ячейку можно делать узкой по высоте.

Модель данных графика

data class GraphItem(
  val id, val screenId,
  val pids: List,   // 2..4
  val colors: List,     // по pid
  val title, windowMin,
  val thickness, grid,
  val autoScaleY
)
// Каждый pid хранит свою шкалу Y (min/max),
// чтобы линии не накладывались. Общая ось X = время.
// История: NavData.history[pid] = RingBuffer(300) (5 мин @1Гц)

В редакторе: кнопка «Добавить график» → диалог: выбрать 2–4 датчика, для каждого цвет (color picker), толщина, окно. Совмещённый график считается одним виджетом типа GRAPH на экране графиков (или отдельным экраном).

Вариант A — несколько кнопок в ActionStrip (рекомендуемый)

Приборы Графики ⋯ Выход

Плюсы: один клик до экрана. Минусы: максимум 4 действия в ActionStrip, «⋯» открывает список дополнительных экранов (до N).

Вариант B — одна кнопка «Экраны» с меню

Экраны ▾ Выход — нажатие открывает Screen со списком экранов (Приборы, Графики, График 2, …, + Добавить).

Плюсы: неограниченное число экранов, не засоряет ActionStrip. Минусы: лишний клик.

Вариант C — свайп/стрелки + кнопки

Стрелки ‹ › по краям поверхности переключают экраны, ActionStrip содержит только «Выход» и «+». Удобно одной рукой, но Car App Library не даёт жесты на surface напрямую — придётся делать невидимые кнопки по краям (Action с иконкой).

Рекомендация: Вариант A для 2–3 экранов + «⋯» для остальных; хранить список экранов в NavLayout (поле screens). В редакторе — вкладки экранов сверху (как в браузере), перетаскивание виджетов между экранами. Все изменения сохраняются одной кнопкой «Сохранить».
