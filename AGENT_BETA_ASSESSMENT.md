# Оценка ветки beta (AA Mazda Monitor) — для следующего агента

Дата: 15.11.2026. Основано на handoff_aa_mazda_monitor_BETA_nav.md (7-я редакция) и анализе репозитория.

## Задумка — 8/10

Дашборд для Mazda SkyActiv-D 1.8 на экране магнитолы через Android Auto (AA): заполнение DPF, температуры ОЖ/АКПП, обороты, скорость. Данные напрямую из ELM327.

Сильные стороны:
- Узкая ниша с реальной болью: владельцы Mazda с дизелем и AA, которым нужно мониторить DPF на экране машины. Готовых решений нет.
- Выбор AA NAV (Car App Library) вместо проекционного API — правильный архитектурный шаг. Документированный API, рисование на всю поверхность.
- Данные напрямую из ELM327 — не зависимость от Torque-приложения, автономность.

Слабые стороны:
- Аудитория критически мала: Mazda 3 2020 дизель с Mazda Connect без тачскрина + проводной AA. Десятки/сотни человек worldwide.
- Привязка к конкретному PID-набору (22 042C, 042D, 0432, 0434, 7E1 22 1E1C) — не универсально.
- GPL-3.0 форк AA Torque — лицензионные ограничения на распространение.

## Реализация — 7/10

Хорошо:
- Раскладка в долях (0–1) — работает на любых экранах.
- Два интерфейса в одном приложении: старый (проекционный) + новый (NAV). Плавный переход.
- Редактор раскладки на телефоне — настройка без перекомпиляции.
- Темы перенесены из старого интерфейса — единый визуальный стиль.
- Surface rendering через Choreographer — плавная анимация, сглаживание.

Проблемные места:
- Kotlin не компилировался ни разу — всё проверяется через CI и фото. Огромный риск.
- Python-скрипты как метод правок — хрупко. Якоря могут не совпасть. Нет IDE-проверки.
- Beta отстала от master на 4+ релиза — рассинхронизация. Пользователи beta не получают фиксы безопасности.
- RegenTracker у беты пустой (SharedPreferences разные у пакетов) — «Интервал» не работает, заменён на «После прожига».
- debugOverlay = false жёстко — скрытый переключатель отладки не сделан.
- Числа шкалы — приближение, не из библиотеки. Касание делений, некрасивый шаг 22.5 при максимуме 180.

## Перспективность — 6/10

В пользу:
- Навигационный интерфейс AA — это будущее. Проекционный API устаревает.
- Редактор раскладки — уникальная фича.
- Прямое чтение ELM327 — не привязан к конкретному приложению-посреднику.
- Открытый код — сообщество может расширить PID-набор.

Ограничения:
- Нишевость: Mazda дизель + AA. Расширение требует новых PID-маппингов.
- Зависимость от AA: Google может изменить Car App Library.
- Один разработчик, работающий с телефона — скорость развития ограничена.
- GPL-3.0 — коммерциализация невозможна без смены лицензии.
- Подмодуль speedviewlib (форк SpeedView) — зависимость от чужого репозитория.

## Вердикт

Задумка отличная для личного проекта и сообщества энтузиастов. Реализация амбициозна, но методология (Python-скрипты, отсутствие компиляции, работа с телефона) создаёт технический долг. Перспективность как продукта — низкая из-за нишевости; как open-source-проекта для Mazda-владельцев — средняя-хорошая.

Главные риски: (1) отсутствие синхронизации beta↔master, (2) нет компиляции/тестов, (3) один разработчик = bottleneck.

## Контекст для продолжения работы

- Ветка beta: version 0.8.2, на базе master ~0.8.2 (слияние 13.11.2026).
- Патчи 1–11 применены, №12 (новый редактор, вариант C) выдан, не применён — ждёт команды.
- Открыто: пропорции предпросмотра (Mazda/эмулятор или адаптивные), максимумы приборов (скорость 180, обороты 6000).
- Слияние 0.8.4 стоит в очереди. Конфликты: AndroidManifest, SettingsFragment, build.gradle, ObdBridgeService, strings.
- Правила: задачи по одной по команде пользователя; версию повышать только по команде; не упоминать стороннее дизельное приложение по имени; AppTheme и 28 тем не менять; beta не трогать без команды.
- Пользователь работает только с телефона: команды для Codespaces, Upload файлов, YAML одной строкой.
- Секреты не печатать; artifacts/ не коммитить.
- Подмодуль speedviewlib: в Codespaces клон по SSH не работает, подменять адрес локально.
- GitHub releases: 0.8.4–0.8.7 с APK на master. Beta не имеет релизов (OTA_ENABLED false).
