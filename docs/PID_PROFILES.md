# Профили PID (P2): как добавить датчик и подготовить профиль

Цель: поддержать всю линейку SkyActiv-D (Demio, CX-3, Axela, CX-30, Mazda3 и др.)
без переписывания приложения — через наборы (профили) PID. Сейчас в коде один
профиль «Mazda SkyActiv-D 1.5 (Mazda2 S5-DPTS)», построенный по таблице Torque Pro.

## 1. Что нужно от тестера (данные для нового профиля)

Минимальный пакет:

1. **Модель и год** (например «Mazda CX-3 1.8 SkyActiv-D 2019») и тип КПП.
2. **Ответы блока на стандартные PID** — экспорт из Torque Pro («Manage custom
   PIDs → Export») или лог чтения `0100`/`0120`/`0140`/`0160` (маска поддержанных).
3. **Ответы на расширенные PID `22xxxx`**, которые возвращает этот блок. Для
   каждого: сырой ответ адаптера (например `62 04 34 01 23 45`) и расшифровка
   в единицах измерения.
4. **Формула пересчёта** байтов в значение (как в Torque: `A`, `B`, `(A*256+B)/4`).
   Если формула неизвестна — достаточно сырого ответа и ожидаемого значения
   с приборной панели.
5. **Диапазон** `min`/`max` и, при необходимости, красная зона (для приборов).
6. **VIN-префикс** (опционально) — для автовыбора профиля.
7. **Результат опроса** `PidProbe`: какие PID отвечают, какие — «нет ответа»
   (в редакторе дашборда они помечаются «· нет ответа»).

Данные присылаются текстом/CSV; секретов и VIN целиком не нужно.

## 2. Как добавить один датчик (сейчас, до профилей)

Шаги:

1. **Строка названия** — добавить в `app/src/main/res/values/strings.xml` и
   `values-ru/strings.xml`:
   `pid_<id>_name`, `pid_<id>_short`, `pid_<id>_unit` (unit можно опустить,
   тогда `unitRes = 0`).
2. **Формула** — добавить метод в `MazdaDecode` (в `PidDecoding.kt`), чистая
   функция от `IntArray`. Покрыть тестом в `MazdaDecodeTest`.
3. **Запись в каталог** — добавить `PidDef` в `MazdaPids.all` (`Pids.kt`):
   - `id` — короткий идентификатор в стиле Torque (например `ff901c`);
   - `request` — команда адаптеру (`"010C"` или `"220434"`), `header` если блок
     не двигатель (`"7E1"`);
   - `min`/`max`, `slow = true` для редких/тяжёлых PID;
   - `decode = { MazdaDecode.xxx(it) }` или `virtual = { e -> ... }` для
     расчётных.
4. **Сборка и тесты**: `./gradlew assembleRelease testReleaseUnitTest`.
5. **Проверка на машине**: датчик появится в редакторе дашборда; при опросе
   `PidProbe` пометит его «нет ответа», если блок не отвечает.

Новые PID не удалять из каталога — только добавлять; фильтрация по поддержке
делается автоматически.

## 3. Планируемая схема профиля (P2, не реализовано)

Профиль — набор:

- `id`, `name` (модель/двигатель), `vinPrefixes: List<String>`;
- `pids: List<PidDef>` (или ссылки на глобальный каталог по `id`);
- `maxOverrides: Map<pidId, Double>` для max шкал;
- `redZones: Map<pidId, Float>`.

Выбор профиля: по VIN-префиксу при подключении, иначе ручной выбор в
настройках (новая категория рядом с `navCat`). Хранение — отдельные
SharedPreferences `pid_profile` (не смешивать с `nav_layout`).

Тесты: unit для декодирования (уже есть `MazdaDecodeTest`), для выбора профиля
по VIN и для сериализации профиля. `NavLayoutStore` сериализацию тестировать
нельзя на JVM (org.json — Android stub) — для профилей использовать
`kotlinx.serialization` или ручной парсинг, чтобы тестировать.

## 4. Что уже сделано как задел

- `PidProbe` опрашивает нестандартные PID при подключении, помечает
  «нет ответа» в списке датчиков редактора. Результат сохраняется между
  подключениями (`probe_missing`/`probe_done` в `obd_bridge`) и показывается
  в настройках OBD строкой «Датчики машины»: сколько ответило и какие PID молчат.
- Каталог пополнен датчиками SkyActiv-D из Torque Pro (`ff9015`–`ff901b`).
- Декодеры вынесены в чистый `MazdaDecode`, покрыты тестами.
- Шкалы и красная зона настраиваются в редакторе дашборда.
