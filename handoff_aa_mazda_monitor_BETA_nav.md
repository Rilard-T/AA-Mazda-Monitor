## 1. Цель и устройство
Дашборд на экране автомобиля через Android Auto (AA): заполнение сажевого фильтра (DPF), интервалы прожигов, температура ОЖ и АКПП, обороты, скорость. Автомобиль: Mazda 3 2020, дизель SkyActiv-D 1.8, магнитола Mazda Connect (**без сенсорного экрана**, управление джойстиком/крутилкой), AA проводной. Данные идут напрямую из адаптера ELM327.

Проект: форк AA Torque (GPL-3.0). Есть два способа рисовать на экране AA:
- **Старый проекционный интерфейс** (в `master` и в `beta`): окно обычного приложения AA, неофициальный API (`CarService`, `MainCarActivity`).
- **Новый навигационный интерфейс AA NAV** (только в `beta`, пакет `com.aadash.nav`): документированная Car App Library, рисуем на всю поверхность AA. Это основная линия развития беты.

## 3. Архитектура навигационного интерфейса (пакет `com.aadash.nav`)
Данные: `ObdBridgeService` (пакет `com.aadash.obd`, общая с основным приложением часть кода) читает ELM327. `ObdBridgeService.peek(id)` нельзя вызывать из главного потока. Таблица параметров `MazdaPids.all` (`PidDef`: `id`, `name`, `shortName`, `unit`, `min`, `max`) в `obd/Pids.kt`.

Файлы `app/src/main/java/com/aatorque/nav/`:
- **`NavCarAppService.kt`**: `NavSession`, `NavScreen`, `NavigationTemplate` с одной кнопкой «Выход»; `SurfaceCallback` = `NavRenderer(carContext)`. `HostValidator.ALLOW_ALL_HOSTS_VALIDATOR`. Манифест: категория `androidx.car.app.category.NAVIGATION`, разрешения `NAVIGATION_TEMPLATES`, `ACCESS_SURFACE`, `automotive_app_desc.xml` с `template`.
- **`NavLayout.kt`**: модель и хранение раскладки.
  - `NavItem(id, kind, pid, label, unit, min, max, scale, decimals, x, y, w, h, size)`: `kind` = `gauge` или `info`; `x,y,w,h` в **долях видимой области** (0–1); `size` = доля вписанного круга для прибора; `scale` для оборотов 0.001 (шкала ×1000, `min 0`, `max 6`).
  - `NavForm(items)`, `NavLayout(narrowAspect, forms, theme = "", ticks = true)`; формы `"wide"` и `"narrow"`. Форма выбирается по пропорциям области: `narrow`, если ширина < высота × `narrowAspect` (1.15).
  - `NavLayoutStore`: `layout` (volatile), `fastPids`/`slowPids` (из раскладки: приборы быстро, значения раз в секунду), `load(ctx)`, `save(ctx, layout)`, `reset(ctx)`, `toJson`/`parse`, `defaultLayout()`. Хранилище: SharedPreferences `nav_layout`, ключ `layout_json`. JSON: `{"v":1,"narrowAspect":1.15,"theme":"","ticks":true,"forms":{"wide":{"items":[{"id":"g0","kind":"gauge","pid":"0d","label":"Скорость","unit":"км/ч","min":0,"max":240,"scale":1.0,"dec":0,"x":0,"y":0,"w":0.333,"h":0.84,"size":0.765},...]},"narrow":{...}}}`. Битый или неполный JSON тихо заменяется стандартной раскладкой (широкая форма не должна быть пустой).
  - Стандартная раскладка: широкая: три прибора в ряд (скорость `0d` 0–240, обороты `0c` ×1000 0–6, средний прибор `size 0.9`, температура ОЖ `05` 40–120; боковые `size 0.765`), снизу четыре значения высотой 0.16 (`ff9010` DPF %, `ff9003` сажа г/л, `ff9005` АКПП °C, `ff9002` «После прожига» км). Узкая: приборы столбиком слева (ширина ячейки 0.45), значения списком справа.
- **`NavData.kt`**: фоновый поток опроса (`peek`), приборы каждые ~30 мс, значения раз в секунду, по списку из `NavLayoutStore`.
- **`NavPainter.kt`**: общее рисование элементов (прибор, значение, фон) для машины и для предпросмотра; `theme: NavThemeRes?`, `ticksOn`. Без темы рисует «плоский» вид (круг, дуга, деления, стрелка), с темой (см. раздел 5) картинки старого интерфейса. Показание прибора рисуется **в центре круга** (`gaugeTexts`: показание размером `0.30·r` с базовой линией `cy + 0.11·r`, единицы `cy + 0.30·r`, название `cy + 0.86·r`). Числа шкалы рисует `tickLabels` (только при теме с делениями; для плоского вида чисел нет). `NavThemeRes` получила поля `tickPaddingDp` (из `sv_tickPadding`) и `tickRotation` (из `sv_tickRotation`, функция `bool`).
- **`NavRenderer.kt`**: рисование по `Choreographer` в своём потоке (`lockHardwareCanvas`, запасной `lockCanvas`), сглаживание показаний 0,12 с, плавное перетекание границ области (0,25 с); берёт раскладку из `NavLayoutStore.layout` каждый кадр; при `onSurfaceAvailable` вызывает `NavLayoutStore.load`. Область берётся по `visible` (запас: `stable`, потом вся поверхность). `debugOverlay = false` (рамки и надпись отключены).
- **`NavTheme.kt`**: `NavThemeRes` и `NavThemes.load(ctx, название)`/`names(ctx)`: загрузка картинок темы старого интерфейса (раздел 5).
- **`NavEditorView.kt`**: предпросмотр на телефоне с касанием (перемещение, ручка размера в правом нижнем углу).
- **`NavEditorActivity.kt`**: экран редактора (интерфейс собирается кодом, без XML).

Вход в редактор: главный экран настроек (`prefs/SettingsFragment.kt`, `res/xml/settings.xml`), группа «**Дашборды AA NAV**» (ключ `navCat`) с пунктом «Раскладка приборов» (ключ `navEditor`) после группы «Дашборды»; обработчик нажатия в `SettingsFragment.onCreate` открывает `NavEditorActivity` (у активности `exported=false`, отдельного значка нет, тема `@style/Theme.App.Settings`).

Редактор (**текущий, применённый**, вертикальная колонка кнопок; в альбомной ориентации предпросмотр сжимается в ноль, поэтому решено переделать, см. раздел 8): кнопки «Широкая», «Узкая», «Пропорции» (только пропорции предпросмотра: Mazda весь экран 2.59, с виджетом 2.27, эмулятор 2.13; колонка Mazda 0.92, эмулятор 0.73; **на рисование в машине эти значения не влияют**, там берётся реальная видимая область); «Датчик…» (выбор из `MazdaPids.all`, для оборотов шкала ×1000), «Добавить» (прибор или значение, по центру текущей формы), «Удалить»; «Датчики во все формы» (копирует датчики по `id` из текущей формы в остальные, положение и размер не меняет); «Сбросить»; «Назад» (спрашивает при несохранённых правках; стрелка в заголовке и системная кнопка так же); «Сохранить» (применяется в машине сразу, служба AA в том же процессе); «Тема…» и «Деления вкл/выкл». Бегунок «размер круга» (30–100% ячейки) для выбранного прибора. Несохранённые правки определяются сравнением JSON с исходным.

## 5. Темы старого интерфейса (что известно и что перенесено)
- Тема в приложении: стиль `AppTheme.*` (27 штук). Список названий в `R.array.Themes`, стилей в `R.array.ThemeList` (одинаковый порядок); выбранная тема в основных настройках хранится строкой в datastore (`selectedTheme`, например «Mazda gen4»); `mapTheme(context, name)` в `prefs/DashboardPreviewFragment.kt` (неизвестное имя даёт `AppTheme_AudiVC`).
- Атрибуты темы (приложение): `themedDialBackground` (PNG циферблата с делениями), `themedEmptyDialBackground` (без делений), `themedNeedle` (PNG стрелки), `themedNeedleColor`, `themedCarBackground` (фон экрана); библиотека SpeedView: `sv_indicator` (в 11 темах `HalfLineIndicator`), `sv_indicatorColor`, `sv_indicatorWidth`, `sv_withIndicatorLight`, `sv_tickPadding` и др.
- Как рисует старый интерфейс: `TorqueSpeedometer` (`stats/TorqueSpeedometer.kt`, наследует `ImageSpeedometer` библиотеки speedviewlib); циферблат задаётся как фон вида (`ViewAdapter.kt`, `setBackground` по `tickNumber`: 0 даёт пустой циферблат, иначе с делениями); стрелка-картинка `SizedImageIndicator` с границами `(0,0,size,size)` на весь квадрат вида, поворачивается вокруг центра (`90 + угол`, угол 135…405 градусов). Стрелка-картинка используется, если `sv_indicatorColor` равен `1996533487` (0x7700AEEF) или `-14575885` (0xFF2196F3); иначе остаётся встроенный индикатор SpeedView.
- **Библиотека speedviewlib** лежит в подмодуле `lib/speedviewlib` (модуль `lib/speedviewlib/speedviewlib`, `ImageSpeedometer.kt` в `.../src/main/java/com/github/anastr/speedviewlib/`); как её скачать в Codespaces, см. раздел 2. Код `Gauge`/`Speedometer` получен 15.11 (подписи шкалы описаны ниже); `ImageSpeedometer.kt` целиком не читали.
- **Перенесено (патч `make_nav_theme.py`)**: PNG циферблата на весь квадрат прибора, PNG стрелки с поворотом `225 + 270·доля` градусов, фон темы, переключатель делений (отдельный от основных настроек, по решению пользователя: настройки двух интерфейсов раздельные). Значение по умолчанию «Плоская» (без темы). Тема и деления входят в JSON раскладки (`theme`, `ticks`).
- **Перенесено (патчи `make_nav_center.py` и `make_nav_numbers.py`, 15.11)**: показание в центре круга; числа на шкале. По коду библиотеки: `Speedometer.drawTicks` рисует подпись i-й точки на угле `135 + 270·i/(N−1)`, значение `min + (max−min)·i/(N−1)`, верх текста на `initTickPadding + padding + tickPadding` от края вида; по умолчанию подпись поворачивается вместе с делением (`sv_tickRotation`); размер и цвет текста из `sv_textSize` (в базовой теме 12sp) и `sv_textColor` (в базовой теме прозрачный, белый задаёт `fragment_gauge.xml`). В старом интерфейсе подписей `NUM_TICKS = 9` (`TorqueGauge.kt:29`), формат задаёт `tickFormatter` из `TorqueGauge.kt` (**не видели**; при желании точного совпадения запросить `grep -n -B3 -A20 tickFormatter app/src/main/java/com/aatorque/stats/TorqueGauge.kt`). Тема «Mazda gen4»: `sv_tickPadding` 14dp, `sv_tickRotation` false, текст белый.
  В `NavPainter.tickLabels`: число подписей N по диапазону `max − min` (целый диапазон 2…12 даёт N = диапазон + 1, диапазон кратный 0,5 даёт шаг 0,5, иначе N = 9); значения из `min`/`max` прибора, то есть в масштабе прибора (обороты в тысячах, своя отсечка на каждой машине, пользователь это требует сохранять); радиус центра подписи `r·(0.80 − tickPaddingDp·0.008)` в пределах 0,55…0,85 r (приближение, не из библиотеки); размер текста `max(0.085·r, 9)`. **Замечания по скриншоту 15.11 (редактор):** подписи работают, но «210»/«240» касаются больших делений; при максимуме 180 получится шаг 22,5 (некрасиво). Правки стоят в очереди (раздел 8).
- **Не перенесено**: свечение индикатора (`sv_withIndicatorLight`); точная форма `HalfLineIndicator` (для 11 тем без картинки-стрелки рисуется линия цвета темы от 30% до 80% радиуса, приближённо); числа шкалы для «плоского» вида без темы.
- Картинки и ссылки загружаются по именам атрибутов (`getIdentifier`), чтобы не зависеть от `R.attr` библиотеки.

## 6. Параметры автомобиля (кратко; подтверждены на машине, кроме отмеченного)
CAN 11 бит 500 кбит/с, блок двигателя 7E0/7E8, АКПП 7E1/7E9. `22 042C` накопление сажи, `22 042D` генерация сажи: (A·256+B)·100/65536 г/л. `22 0432` счётчик регенераций. `22 0434` пробег после прожига (`ff9002`): ((B<<16)+(C<<8)+D)·100/65536 км. `7E1 22 1E1C` температура АКПП (`ff9005`). `22 0380` статус прожига (0/1/2). Стандартные режима 01: температура ОЖ `05`, обороты `0C`, скорость `0D`. «DPF %» (`ff9010`) расчётная: сажа / порог ×100, порог задаёт пользователь. Чтение DTC не нужно.

**«Интервал» (`ff9011`) в бете не показывается**: параметр расчётный, он берётся из журнала прожигов `RegenTracker` (список пополняется, когда счётчик `ff9001` вырос во время работы приложения; хранится в SharedPreferences `obd_bridge`, которые у каждого пакета свои). У беты журнал пустой, поэтому был прочерк. В AA NAV ячейка заменена на **«После прожига» (`ff9002`)**, читается прямо с блока и от журнала не зависит.

## 8. Очередь задач и открытые вопросы (каждую начинать только по команде)
1. **Новый редактор (`make_nav_editor2.py`, №12) и адаптивные пропорции.** Решено пользователем: вариант C (предпросмотр на весь экран, меню элемента по **удержанию** на приборе, не выезжающая панель). Ждём «применяй». Дополнительно пользователь спросил, можно ли отказаться от фиксированных размеров Mazda/эмулятора (они влияют только на предпросмотр, в машине рисование идёт по реальной видимой области, раскладка в долях). Предложено два варианта, **ответа нет**: (1) рекомендуемый: `NavRenderer` запоминает реальные пропорции области отдельно для `wide` и `narrow` (например в SharedPreferences), редактор использует их, стандарт до первой поездки около 2,4 (широкая) и 0,8 (узкая), пункты «Пропорции» и список Mazda/эмулятор удаляются (заодно из меню «⋯» в скрипте №12, поэтому лучше внести в №12 до применения); (2) предпросмотр подстраивается под экран телефона, форма выбирается по ориентации (проще, но пропорции отличаются от машины).
2. **Настройка максимума приборов («Шкала…»).** Требование пользователя: задавать максимум скорости и оборотов (у него лимит скорости 180, обороты 6000; на других авто иначе). Решения: кнопка «Шкала…» в меню элемента (после №12), ввод числа цифрами (для оборотов в оборотах, внутри хранится в тысячах), применяется ко всем приборам с тем же датчиком во всех формах, минимум не трогать; при выборе датчика кнопкой «Датчик…» уже введённый максимум для того же датчика не сбрасывать. **Стандартные значения: скорость 240, обороты 8** (сейчас в коде `itemFromPid` и `defaultLayout` у оборотов `max 6`: поменять на 8; пользователь сам введёт свои). Заодно: подбор «круглого» шага подписей (для 180: 0, 20 … 180; 240: шаг 30; обороты 0…8 шаг 1) и сдвиг подписей чуть внутрь (базовая 0,80 → около 0,75).
3. Слияние `master` 0.8.4 → `beta` (раздел 2): страховочная ветка `backup-beta-0.8.4`, затем merge, проверка конфликтов, `grep` манифеста.
4. **Проверка двух входов в одном приложении:** старая служба `CarService` (проекционный интерфейс) и `NavCarAppService` вместе в `beta`; раньше основное приложение и бета (разные пакеты) прятали друг друга в списке AA (подозрение: общее действие `org.prowl.torque.remote.TorqueService`); если оба входа в одном пакете не покажутся одновременно, запасной вариант: переключатель в настройках, включающий один вход и отключающий другой. Настройки двух интерфейсов решено сделать раздельными. (Подмодуль `speedviewlib` для этого нужен в любом случае.)
5. Скрытый переключатель отладки областей в настройках (для чужих устройств); третья форма раскладки для режима с виджетом (сейчас «с виджетом» использует форму `wide` с другим предпросмотром; при адаптивных пропорциях этот вопрос упрощается).
6. Доработки редактора: выравнивание/сетка при перетаскивании, подписи размеров, возможно текстовые поля для точных значений; удаление и добавление окошек всех форм сразу.
7. Числа шкалы: точное совпадение формата со старым интерфейсом (нужен `tickFormatter` из `TorqueGauge.kt`), числа для плоского вида без темы.
8. Редизайн Android Auto «Cielo» (анонс май 2026): перепроверить после выхода 18.1 или 19.
- Открыто: как ведёт себя полоса с «Выход» (скрывается ли из кода; пока только джойстик); реальные размеры областей на других магнитолах; BLE/Wi-Fi адаптеры на практике не проверены; как показание в центре и числа шкалы смотрятся в машине (фото после патчей №10–11 пользователь ещё не присылал).

## 9. Правила работы (от пользователя)
- Задачи строго по очереди и только по его команде («давай», «начинай», «делай»). Версию повышать только по его команде. Несколько задач сразу он иногда просит: делай по одной, остальное ставь в очередь.
- Все инструкции выполнимы с телефона: «куда нажать», команды для терминала Codespaces, Upload файлов. YAML только одной строкой (JSON-стиль).
- Правки только идемпотентными скриптами на Python (проверять на макете, собранном из присланных дампов) или архивом с `.kt`. Порядок: загрузить в корень репозитория → выполнить `python3 имя.py && rm имя.py` → Commit → Sync Changes → Actions. В конце ответа: что делает правка, куда нажать, что проверить.
- Файлы смотреть по присланному дампу, а не угадывать пути (например, `SettingsActivity.kt` лежит в `prefs`, `TorqueSpeedometer.kt` в `stats`). Дамп: команда в терминале в файл `state.txt` (затем Download, прислать, `rm state.txt`).
- Честно говорить о непроверенном: код не компилировался, на машине проверяет пользователь. Ошибки сборки разбирать по архивам логов Actions (красный запуск → ⚙ → Download log archive; искать `e:` и `What went wrong`).
- Не упоминать по названию стороннее приложение для дизелей Mazda в проекте и текстах приложения. Лицензионные пометки (GPL-3.0, авторы Kyle Agronick, Chillout, Martoreto, авторы иконок CC BY 3.0) сохранять. Не хранить токены и пароли; файл ключа подписи не коммитить.
- README.md без прямой просьбы не менять. Чейнджлоги выпусков на русском и английском (формат релиза 0.7.5), отдельно текст коммита.
- Не путать эмулятор Headunit Reloaded с реальной магнитолой.
- Для визуальных вопросов («покажи до применения») удобно показывать схематичный интерактивный макет (портрет, альбом, состояния меню); пользователь это оценил и выбирает дизайн вместе с ассистентом: предлагай 2–3 варианта и жди выбора.
- В скриптах тексты на русском, без лишних зависимостей; после правки код проверяется по сборке Actions и по фото/скриншотам пользователя.
- Приложение пишется для себя, но должно работать на любом устройстве с AA, любыми размерами и диагоналями: всё хранить долями и в dp, не привязываться к 1196×462.
